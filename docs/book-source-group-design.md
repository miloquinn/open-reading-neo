# 书源分组与校验结果设计

## 目标

在现有书源管理页中补齐两类不同需求：

1. 用户可以按最近一次校验结果快速找到正常、异常和未校验书源。
2. 用户可以创建自己的分组，并对单个或多个书源维护分组归属。

本设计参考 Legado 书源 JSON 的 `bookSourceGroup` 兼容语义，但不把动态校验结果写入该字段。

## 已有基础

- `RegisteredBookSource.sourceConfig.bookSourceGroup` 已能被解析为多个分组。
- 管理页已支持按导入分组搜索、筛选，并在书源卡片展示最多两个分组。
- 管理页已有多选模式、批量校验和单源重新校验。
- `SourceHealthCheckResult` 已持久化最近校验时间、耗时、已检查能力、失败能力和超时状态。
- 当前缺少分组的创建、改名、删除和批量归属操作；导入分组实际上是只读的。

## 核心原则

### 校验状态和用户分组是两个维度

校验状态是系统根据最近一次校验动态计算的视图：

- **正常**：最近一次校验完成，所有实际检查的能力均成功。
- **异常**：最近一次校验存在失败能力或超时。
- **未校验**：没有可用的历史校验结果。
- **校验中**：仅在当前页面任务执行期间展示，不持久化为分组。

用户分组是用户维护的长期分类，例如“常用”“备用”“小说”“待整理”。一个书源可以属于多个用户分组。

这样设计可以避免一次重新校验就改写用户整理结果，也能表达“常用 + 异常”“小说 + 未校验”等组合条件。

### 不自动停用或删除异常书源

校验受网络、登录状态、站点限流和规则链影响。异常只表示最近一次检查的结果，不等于书源永久失效。批量校验完成后只更新状态，由用户决定停用、重新校验、调试或删除。

## 信息架构

### 管理页筛选区

保留搜索框，在下方提供两层筛选：

1. **快捷状态**：全部、已启用、已停用、正常、异常、未校验。
2. **更多筛选**：可直接使用、缺少可执行规则、需要登录、协议类型。

“我的分组”作为独立筛选入口，不混入状态枚举：

- 全部分组
- 未分组
- 用户创建或从导入数据迁移的分组
- 管理分组

状态筛选、分组筛选和关键词搜索取交集。例如选择“异常”与“常用”，只显示“常用”分组中最近校验异常的书源。

### 列表展示

列表继续按协议分区，避免改变现有 ORSP 与兼容书源的层级。书源卡片展示：

- 异常或超时：错误语义图标与简短状态。
- 正常：克制的成功图标；不为每张卡增加大面积绿色背景。
- 未校验：默认不增加徽标，详情或筛选时再明确显示。
- 用户分组：最多展示两个；其余显示“+N”。
- 最近校验时间和失败能力放在卡片详情或操作菜单中，避免列表过密。

### 多选操作

多选工具栏新增“分组”操作。点击后打开分组面板：

- 复选框支持一次加入或移出多个分组。
- 多个书源的归属不一致时使用不确定态复选框。
- 提供“新建分组”。
- 保存时只修改分组，不改变启用状态和校验结果。

单个书源的更多菜单增加“编辑分组”，复用同一面板。

### 分组管理

“管理分组”页面或底部面板提供：

- 新建分组。
- 改名，并原子更新所有关联书源。
- 删除分组，仅移除归属，不删除书源。
- 显示每个分组的书源数量。

分组名规则：去除首尾空白、不可为空、不允许逗号/分号/换行等兼容字段分隔符、最长 30 个可见字符；名称比较忽略大小写，保留用户输入的显示形式。

## 校验完成后的反馈

批量校验完成后显示结果摘要：

`已校验 20 个：正常 15，异常 4，未完成 1`

摘要提供两个直接动作：

- **查看异常**：切换到“异常”状态筛选。
- **完成**：关闭摘要，保留当前筛选。

“未完成”用于检查过程抛错且旧状态被保留的情况，不能把它误报为校验失败。超时属于有明确结果的“异常”。

## 数据模型

### 用户分组

在 `RegisteredBookSource` 增加顶层字段：

```dart
final List<String> groups;
```

使用顶层字段而不是直接修改 `sourceConfig.bookSourceGroup`，原因是：

- ORSP 书源没有兼容协议的 `sourceConfig`，也需要支持用户分组。
- `sourceConfig` 是来源配置，重新导入可能刷新；用户分组是本地用户数据，必须保留。
- 后续同步、导出和冲突处理需要明确区分用户数据与来源数据。

存储与迁移规则：

1. 新记录优先读取顶层 `groups`。
2. 老记录没有顶层 `groups` 时，从 `sourceConfig.bookSourceGroup` 解析并迁移。
3. 顶层 `groups: []` 表示用户明确清空，不再次从兼容字段恢复。
4. 同源重新导入或刷新时保留原记录的 `groups`。
5. 新导入书源首次使用其 `bookSourceGroup` 作为初始分组。
6. 导出为 Legado 兼容 JSON 时，将顶层 `groups` 序列化回 `bookSourceGroup`。
7. WebDAV 同步把 `groups` 作为书源记录的一部分；沿用现有记录级冲突规则。

分组本身不需要独立数据库表。当前分组集合可由所有书源的 `groups` 聚合得到；如果将来需要空分组、手动排序、颜色或图标，再引入独立 `BookSourceGroup` 元数据存储。

### 校验状态

不增加“成功分组”“失败分组”字段。使用现有 `SourceHealthCheckResult?` 派生：

```text
null                    -> 未校验
healthy == true         -> 正常
healthy == false        -> 异常
```

健康结果继续保存最后校验时间、耗时和失败能力。首版校验范围维持现状：仅支持当前健康检查器可执行的兼容书源；其他协议显示“暂不支持校验”，不归入正常或异常，避免制造假结果。

## 服务与状态接口

建议在 `BookSourceRegistry` 增加原子批量操作：

```dart
Future<List<RegisteredBookSource>> setGroups(
  Iterable<String> sourceIds,
  Iterable<String> groups,
);

Future<List<RegisteredBookSource>> renameGroup(
  String previousName,
  String nextName,
);

Future<List<RegisteredBookSource>> deleteGroup(String name);
```

控制器增加独立的健康筛选枚举，避免继续膨胀现有通用状态枚举：

```dart
enum BookSourceHealthFilter { any, healthy, unhealthy, unchecked }
```

筛选顺序固定为：协议可见性 -> 通用状态 -> 健康状态 -> 用户分组 -> 搜索关键词。

## 边界与错误处理

- 重新导入同一书源不得覆盖本地分组和已有校验结果。
- 分组改名/删除必须一次写入完成，失败时不留下半更新状态。
- 删除最后一个分组归属后，书源进入虚拟“未分组”，书源本身不受影响。
- 当前选中的分组被删除时，筛选自动回到“全部分组”。
- 校验中禁止对同一批书源重复发起校验，但不阻止搜索和切换筛选。
- 取消或页面销毁后忽略迟到进度；已成功持久化的单源结果仍可在下次进入页面时显示。
- 分组筛选必须继续支持大量书源的分页展示，不因状态徽标或分组聚合改变列表高度稳定性。

## 分阶段实现

### 第一阶段：可用闭环

- 顶层 `groups` 字段及旧数据迁移。
- 正常、异常、未校验筛选。
- 单源与批量编辑分组。
- 新建、改名、删除分组。
- 批量校验结果摘要和“查看异常”。

### 第二阶段：效率增强

- 分组排序、空分组保留、分组颜色或图标。
- 按分组一键全选并校验。
- 记住上次筛选条件。
- 按失败能力细分筛选，例如“搜索失败”“正文失败”。

首版不做自动周期校验、异常自动停用和复杂标签规则。这些行为涉及后台网络、误判成本和电量消耗，应单独设计。

## 验收标准

- 老数据中的 `bookSourceGroup` 无损显示并可编辑。
- ORSP 与兼容书源都能加入用户分组。
- 一个书源可同时属于多个分组，搜索和筛选结果正确。
- 校验后书源自动进入正确的状态视图，但用户分组不变。
- 未校验书源不会被归为失败；执行异常且未产出结果的书源不会覆盖旧结果。
- 重新导入或刷新书源后，用户分组和最近校验结果仍保留。
- 改名和删除分组不会删除、停用或重复任何书源。
- 多选操作、窄屏布局和大量书源增量加载均有 widget/controller 回归测试。
