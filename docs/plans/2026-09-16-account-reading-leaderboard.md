# 账号阅读统计与排行榜

## 用户行为

- 入口：详细统计页的「账号统计与排行榜」、账号页的「账号阅读与排行榜」。
- 原有详细统计标注为「本机阅读统计」；账号页展示服务端合并后的账号总时长、本周、本月，以及周榜、月榜、自己的名次。
- 登录后的前台阅读自动记录，断网保存在本机；登录凭证过期或离线重启仍归原账号，主动退出才改为游客。切换账号立即切换页面缓存和新记录的归属。
- 游客历史需要在页面确认合并。确认后先在本机固定归属，再上传；上传失败也不能被另一个账号认领。游客、旧版历史均不参与排名。
- 公开上榜默认关闭。开启后展示昵称、头像、时长；关闭即退出公开排名，个人统计仍保留。接口不上传书籍正文、书名、书单或设备硬件标识。
- 阅读器加载完成、位于当前路由且前台可见时计时；应用隐藏、失焦、切到其他页面或启动朗读时停止本次云端计时。听书暂不单独提供排行榜。

## 数据与边界

客户端 SQLite v26 新增 `reading_cloud_events`、`reading_cloud_cache`、`reading_cloud_meta`，原有本机统计不改写。阅读计时每分钟保存不可变的 UUID 记录；正常离开页面、切账号、进入后台立即结算。异常强杀可能丢失最后一个未保存的分钟片段。

云同步只从自己的 outbox 上传，不扫描后续导入的 `reading_sessions`。WebDAV/本机备份恢复的历史不会自动重新上传或获得榜单成绩。WebDAV 备份功能与账号云同步分别负责设备资料恢复和账号阅读统计。

升级时对已有数据做一次历史快照：有会话明细的日期以明细为准；没有明细的日期保留日汇总。明细导入采用稳定 ID，日汇总采用持久化的本机迁移来源 ID，避免不同用户碰巧有相同时长时发生冲突。旧版只有日汇总时无法还原跨设备重叠，云端保守地取该日旧历史基线的最大值，再合并新版记录，不把多个不明来源的日总数直接相加。

服务器 `reading_events.event_id` 全局唯一。相同账号、相同内容的重试成功；不同账号或同 ID 不同内容返回逐条冲突，不修改原始记录。被拒绝的记录保留在本机并在页面提示。每个请求同时携带预期账号 ID，服务端与 Bearer 会话核对，避免账号切换期间读错或写错账号。

上传队列、回执、本机缓存均绑定账号；晚到的 A 请求可确认 A 的队列，但不能覆盖 B 的界面。后台阅读请求不自行刷新全局 token，凭证刷新仍由账号生命周期负责。

## 统计规则

- 周期统一为 Asia/Shanghai（UTC+8），周一为每周第一天。
- 服务端按阅读时间段求并集，同账号多设备同时阅读不重复计时，跨午夜拆到各自日期。
- 新版账号阅读最多每段 5 分钟；7 天内补传可计入排名，超过期限仍计入个人统计。重复请求保留最初判定。
- 日聚合每账号最多 86400 秒；服务端拒绝未来时间、非法时长等异常记录。
- 周/月榜使用日聚合，不扫描全站事件。相同时长并列名次（1、1、3），返回前 100 人和当前用户自己的名次。
- 这属于客户端上报的阅读激励榜，不能证明真人持续阅读，暂不绑定有价值奖励。

## 后端

`open-reading-web/app/reading/` 包含模型、仓储、路由和建表语句。复用 PostgreSQL 账号库与现有鉴权，按账号加锁串行化上传/日汇总更新，事件全局唯一约束处理跨账号并发。账号删除通过外键级联删除事件、汇总和上榜设置。

接口：

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/reading/events` | 每批最多 200 条记录，逐条返回 accepted/rejected |
| `GET /api/v1/reading/summary?user_id=...` | 个人总计、周/月时长、最近 90 天统计和公开开关 |
| `PUT /api/v1/reading/preferences` | 设置公开上榜 |
| `GET /api/v1/reading/leaderboard?user_id=...&period=week或month` | 榜单和个人名次 |

接口要求完整账号鉴权，不接受尚未完成 MFA 的会话。返回 `Cache-Control: no-store`，并复用账号限流。新错误码包含网站简中、繁中、英文翻译；App 隐私页补充阅读数据说明。

## 上线与验证

先部署后端，再发布客户端；后端启动时执行增量建表，无需操作现有数据。服务器未升级时，App 显示服务尚未开放并保留待上传记录。此开发任务不自动发布版本或部署生产服务器。

回归覆盖：历史 9 小时一次认领、离线补传、账号切换中的延迟响应、错误账号回执、token 切换、跨设备重叠、跨天统计、并发认领、幂等重试、晚到数据、公开开关、榜单隐私、榜外个人名次、账号删除级联，以及窄屏/大字体 UI。

Flutter Stateful 测试按文件分别启动进程。后端使用显式指定的临时 PostgreSQL/Redis 实例执行全套 pytest 和 Ruff，不使用生产数据库。真机离线/锁屏/强杀与生产接口联调仍需要安装新客户端、部署新后端后验证。

开发验证结果：后端全量 424 项通过，Ruff 通过；新增客户端同步/网络/页面测试 12 项通过，详细统计、账号服务、账号页面、账号注销和会员/隐私页面回归通过，原生阅读器后台暂停与书源章节导航单独验证通过。详细统计测试改用独立临时数据库并逐步推进真实 I/O 与 widget 时钟；注销测试使用独立归属实例和真实 I/O 推进，保留全部原断言。新增模块静态分析无问题。

另外记录两项不属于排行榜的现存问题：`native_reader_auto_page_turn_test.dart` 的 `continuous mode crosses an EPUB chapter without changing mode` 单独运行时仍将 `native-reader-status` 强转为 `Text`，而现有组件已为 `ReaderProgressFooter`；`native_reader_page_cache.dart:159` 的 `onError` 回调返回 bool 与 Future 类型不匹配，静态分析报 warning。本次没有为这些问题修改应用行为，也没有把测试失败归因于平台构建。
