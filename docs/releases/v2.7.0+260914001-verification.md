## Diagnosis and repair

The settings badge read a presentation cache while advanced source access read
live account membership. A failed membership request cleared the live grant;
a failed cold-start session restore had no automatic recovery, and foreground
refresh was limited to the membership page. Restore Purchases could repopulate
the same formal account entitlement, making repeated manual restoration appear
necessary even when the database grant was permanent.

One account-owned synchronization path now handles startup, foreground return,
transient failure recovery, and response ownership. Presentation cache alone
cannot mark an unverified session as Premium. Transport failure does not revoke
a previously verified grant for the same session. Server denial/account change
still invalidates access. An offline cold start remains pending authentication
until reconnection, then recovers automatically without StoreKit restore.

The server status, redeem, Apple purchase and restore responses derive user_id,
premium_sources and purchase_allowed from the same active entitlement set.
Sandbox verification remains separate from formal grants. Existing members see
channel-specific explanations and are rechecked before Apple purchase starts.
