## 本次交付边界（2026-09-05）

- 本地 TXT 阅读器增加「编辑本章」，保存真实原文、撤回未保存修改、转换编码确认和本机版本恢复。阅读器和编辑器共用流式字节索引，按约 32K 字符分段载入，移除整本 64 MiB 编辑及 500 MiB TXT 同步拒绝路径；单次编辑输入仍有 4 Mi UTF-16 单元保护，其他格式的同步沿用 100 MiB。大文件性能数据见 `plans/large-txt-streaming-incremental-sync.md`，不等同于移动端真机验收。
- 固定书籍身份与内容 hash 分离；正文保存、绑定关系、待同步任务和历史快照协同更新。可变 TXT 默认继续使用 v2 普通 TXT 路径和流式条件写入；用户可明确开启 v3 增量模式，内容块按 SHA-256 寻址，版本清单最后条件提交；已有 v2 文件保留但不再自动更新，云端分块需新版 App 读取。每个内容 hash 对应不可变编码描述符，接收时严格验证 UTF-8、GBK 或 UTF-16，支持无 BOM UTF-16。旧 v1 副本保留，界面展示新路径。
- 已绑定 TXT 自动检查双向变化；活动阅读/编辑期间先暂存远端更新，下次开书或用户选择后应用。双方都修改时保留完整两份文件，支持差异预览、保留本机或使用远端。非重叠修改自动合并、远端历史批量管理继续后置。
- 正文变化使定位无法证明有效时保留笔记/书签并标记位置失效，支持复制或删除；不猜测重复摘录的位置。远端整文件替换采用保守失效策略，后续可扩展跨版本精确迁移。
- 进度用稳定内容定位及阅读事件因果关系接续；开书短暂检查，超时先读本机；已在阅读时只提示。并发设备候选、稍后处理和已处理决定持久保存，自动接续可返回原位置。
- 设置入口及首页改为「云端同步」，区分阅读位置和正文任务；自动同步、进度范围、自动接续及单书参与均可控制。新配置的设备排版偏好默认不随云端变化，已有选择保持。
- 同书身份沿用已绑定 UID 或既有内容身份；同名书不自动合并。跨不同内容版本的手动同书关联向导、首次连接的逐书合并预览、首页续读卡片继续后置。新书首次自动上传队列仍受应用进程生命周期限制；加入同步后的正文修订任务已持久化。
- 文件与进度采用独立调度、失败重试和前后台触发；未实现 Wi-Fi 专属传输策略，不承诺应用被系统终止后继续同步，也不承诺其他设备尚未上传时能够立即获得其进度。
- 验证使用本地临时文件、隔离数据库、模拟 WebDAV 和 Flutter UI；不接触用户真实云端。真实 WebDAV 服务商条件请求兼容、两台物理设备和移动端存储提供器仍需现场验收。


## 大文件与增量传输

- 内存只持有当前编辑段、64 KiB 读写缓冲、有限大小的内容块及章节/版本索引；不将整书转换成一个 String。无章节、无换行的超长正文同样分段。
- 本地保存通过流式拼接临时文件并原子替换，仍需顺序读取/写入整书与生成恢复快照；因此大书保存存在磁盘时间与临时空间成本，不承诺局部修改的本地 I/O 为常数。
- v3 内容定义分块的默认最小/目标/最大值为 64 KiB / 256 KiB / 1 MiB。首次同步上传全部缺失数据，后续插入或删除可复用边界重新稳定后的块；无法承诺所有编辑固定只上传一个块。
- 上传先提交不可变块，最后用 ETag 条件写入当前清单；中断后复用已存在块。下载校验块 hash 和整书 hash，完成后才进入原有文件事务。
- 普通 WebDAV 无可移植的局部 PUT/服务端拼接保证，v2 普通 TXT 模式仍需流式重传完整文件。v3 不伪装成云端可被任何文本编辑器直接打开的 TXT；首次选择/升级前显示格式和兼容说明，默认不迁移已有绑定。
- 阅读进度继续走独立的小型事件同步，不等待整本正文传输；内容版本不同则遵循既有定位有效性和冲突规则。
- 当前本地历史与块缓存使用磁盘；自动压缩历史、孤立块回收及云端垃圾回收尚未实现，不能将内存改造描述成零额外存储成本。

## 产品目标

用户一次选择「这本书参与同步」，以后保存正文即排队同步。普通 TXT 模式下云端保留稳定路径的当前 TXT；增量模式下稳定路径保存当前版本清单，正文为不可变内容块，本地始终重建为完整 TXT。历史版本单独保存；另一台已下载该书的设备自动接收内容更新，书架身份、笔记和进度保持关联。

「本地已保存」「已同步到 WebDAV」「另一设备已接收」分别表达，不在本机落盘后就显示所有设备已更新。备份/历史恢复作为次级能力，日常不再依赖上传、恢复和重新导入操作。

## 实施前的行为与升级目标

| 代码确认的当前行为 | 升级目标 |
| --- | --- |
| 启动/回前台触发，距上次成功不足15分钟则跳过 | 保存触发、持久重试、前台检查，新修改不受旧成功时间压制 |
| 元数据双向合并，文件另行上传/恢复 | 协调内容版本及其依赖的笔记/进度 |
| 书籍身份按当前文件SHA256产生 | 固定书籍身份，hash只表示内容版本 |
| 自动上传按标题跳过已有云书，队列仅内存 | 按稳定身份检测文件变更，任务持久化 |
| 同路径不同内容另存编号目录 | 更新同一绑定路径，另存历史版本 |
| 下载走导入器，可能新建book.id | 已绑定书原位更新；未下载书才首次导入 |
| 本地导入500MB，WebDAV文件仅100MiB | 原生 TXT 导入、编辑、同步走流式路径；用 200/500 MiB 实测验证，非 TXT 和 Web 内存导入保留独立限制 |

## TXT 编辑交互

1. 阅读器更多 →「编辑本章」；手机全屏，桌面有最大宽度窗口，顶部取消/保存。
2. 展示解码后的真实 TXT 本章原文，可改字、删字、补写和换行。编辑输入不触发阅读页逐字重排。
3. 长按快捷编辑只在能证明选区到原文的映射准确时开放；净化改变正文导致映射不明时打开本章原文，明确说明，不靠同句搜索猜位置。
4. 保存生成应用管理的 TXT 新版本，保留旧版本。用户最初从其他文件夹导入的源副本不跟着修改；应用原地管理路径需核实写入权限。
5. 保存可靠落盘后回到修改附近。恢复旧内容也生成新版本，可继续同步并再次撤销。

第一版编辑正文，不开放章节标题/结构编辑。保存前检查自然章节边界，避免新增一行被误识别成新章节；大章分片变化必须有原文区间映射，不能只检查章节数量。

## 新设备首次连接与同书关联

连接测试成功后读取远端书架、身份及进度，展示准备合并的范围，再建立初始同步基线。合并可恢复、幂等；未完成引导不能因后台自动任务先把初始化数据发布出去。初始化的未读/0%不是阅读事件，不能覆盖云端已有进度；本机真实阅读产生的0%或回读事件仍保留，双方有分歧走续读候选规则。

首次合并不自动全库下载、不清空本机书架；已有本机未同步阅读记录先保全。元数据接收完成与正文下载完成分别显示；断网保留已完成部分，下次继续。

同书关联遵循以下顺序：

1. 从同步书架下载：直接沿用固定bookUid及内容版本，关联同一本书。
2. 两端独立导入：同一同步空间内全文hash和大小一致、仅有一个未歧义目标，且不冲突于已有固定身份时，自动建立关联；名称相同不足以证明是同一本书。
3. 同名不同内容、多个同hash目标、已经属于不同固定身份：显示候选及差异，允许关联指定书/分别保留。不得自动折叠多个本地书架项或丢掉任一侧笔记、进度。
4. TXT已编辑导致hash不同：已有绑定继续沿用；未绑定时需要用户确认及版本比较。确认“是同一本书”不等于授权用一份正文覆盖另一份，原文与进度都按版本规则保留。

关联成功后继续使用稳定身份，hash仅用于内容验证与首次匹配。仅本机书仍不因匹配到名称就加入文件同步。

### 保存与同步反馈

| 场景 | 状态/行为 |
| --- | --- |
| 已参与同步、在线 | 已保存到本机·等待同步 → 正在同步 → 已同步到WebDAV |
| 已参与、离线 | 已保存到本机·联网后同步 |
| 自动同步关闭 | 已保存到本机·同步已暂停；可手动立即同步 |
| 仅本机的书 | 已保存到本机；提供加入同步，不自动首次上传 |
| 失败 | 保留本机文件及任务，显示同步未完成，可重试 |
| 双边冲突 | 保留双方，继续阅读本机版本，提供对照入口 |

每次保存不再询问是否上传。连续保存合并尚未启动的上传；已开始任务读取固定版本，新保存排在后面。旧版本上传成功不能把较新的待上传版本标成已同步。

## 另一设备如何更新

- 已下载且未打开：自动下载校验，更新同一个本地book.id。
- 仅云端：更新书架信息，不全库自动下载；打开时下载并阅读。
- 正在阅读：后台暂存，轻量提示「正文有更新·应用更新」，点击或下次打开时切换；不突然跳页。
- 正在编辑或有本地未同步修改：先保留远端版本，保存后按共同基线合并，不后台覆盖。
- 下载期间又产生本地保存：应用下载结果前再次检查本地版本，变化则转合并。
- 应用更新时暂停听书/自动翻页，重建搜索和朗读等派生数据，由用户继续。

首次未配置时显示“连接你的 WebDAV，手机和电脑接着读”，提供设置连接；配置好后主屏不常驻服务器URL、根目录和协议说明。连接状态不能作为进度已同步的证据；示例书/设备/时间必须来自真实同步记录，无记录时显示暂无跨设备阅读记录。

手机按上述顺序单列；宽屏左侧续读状态与最近活动，右侧行为/范围设置，服务器配置进入次级页。沿用 Material 主题与已有卡片，不新增主题系统。详情列出书名、章节、设备、发生时间及接收状态；正文传输单列，不能让“进度已同步”掩盖正文版本尚未就绪。

阅读进度同步决定是否交换位置；打开自动接续决定如何使用已接收的位置，关闭后保留手动“接着其他设备读”的入口。总自动同步关闭时两个自动行为暂停，保留用户子项选择；手动同步仍可执行允许的数据范围。新用户开启续读前明确展示默认项，升级保留已有关闭选择。

进度同步不要求上传整本TXT：两端已可靠关联同一本、同内容版本时，只传位置记录即可。正文文件开关独立；可设大文件仅Wi-Fi、进度允许移动网络，均尊重用户全局联网限制。文件同步关闭时若内容版本不同，提示定位暂不可用/需要匹配版本，不能绕过偏好自动传书。

### 单本书的同步详情

至少分项展示阅读位置、正文、本机待同步修改及需要处理项。例如“阅读位置：已接收手机更新”“正文：等待Wi-Fi上传”“本机：还有未同步修改”；设备和时间只来自真实事件。每项提供适用的重试/接续/版本对照入口，成功项不被重复传输。

“最近检查”记录联系服务器的结果，“最近发布/接收”记录具体进度或版本；不能由一次连接成功推导所有设备已同步。没有其他设备回执时，只显示已发布到WebDAV，或本机已接收某设备的更新。

### 排版属于设备偏好

新用户默认不把字号、主题和翻页方式与进度一起同步；续读必须适配各自排版。若已有用户显式开启阅读设置同步，升级保留该选择，并在更多同步内容中提供独立说明与开关。进度开关不能隐式启用排版设置同步，也不强迫B沿用A的页码布局。

### 首页续读卡片（后续增强）

首页/书架顶部提供单个“最近在读”入口，显示书名、章节/百分比、来源设备与“继续阅读”。点击进入与普通开书相同的检查、版本确认和定位链路，不另写一套直接使用缓存进度的导航。

未下载时说明“下载并继续阅读”，遵守文件范围、网络策略及用户下载选择。并发进度无唯一先后时，不按最大百分比强选一条：优先保留本机会话并提供其他设备候选；无有效阅读记录则不显示虚构内容。该卡片不阻塞首期发布。

- 全局页面围绕状态和待处理项；书籍列表主筛选为全部/需要处理/未下载，不以手工上传与下载作为日常主流程。
- 每本书详情显示参与同步开关、当前状态、最后来源设备、版本历史。书库只轻量标记待同步/冲突，不在正文常驻大条幅。
- 已有明确云端绑定的TXT在升级引导中一次说明后续自动更新，保留原有关闭/暂停选择。未绑定同名文件不能靠标题认领。
- 下载一本同步书后持续接收该书更新，但首次下载仍由用户决定。
- 全局自动同步管理调度；每本书参与状态及数据范围管理资格。立即同步也不突破关闭的文件范围。
- 网络策略沿用用户选择；新用户建议文件仅Wi-Fi，可允许移动网络。没有可靠网络识别时不提供虚假的仅Wi-Fi保证。
- 元数据完成、文件失败时显示部分完成；“已连接”不等于“已同步”。无设备回执时不说所有设备已接收。
- 停止同步保留本机和云端文件、暂停任务；重启同步先比较双方，不直接上传覆盖。

## 自动触发

| 时机 | 建议 |
| --- | --- |
| TXT保存 | 立即持久标记，约2秒防抖后协调；时间为待验证参数 |
| 连续进度变化 | 本地及时保存，网络合并节流，退出阅读时刷新队列 |
| 启动/回前台 | 恢复未完成操作，检查本地待同步与远端版本 |
| 网络恢复 | 有系统事件就唤醒，否则靠持久退避重试兜底 |
| 保持前台 | 建议30～60秒轻量检查活动/已下载书籍及设备变更；无变化不下载全文 |
| 手动同步 | 同一协调器立即处理，避免第二套并发任务 |

同书串行、不同书限流。应用完全退出后不承诺继续联网；承诺任务不丢、下次获得运行机会续传。真后台能力按平台另行验证。

## 跨设备无感续读

### 目标与坐标

场景：A设备读到某段，进度成功发布后，在B打开同一本书，第一屏就接续该段。无需进入设置、点下载/恢复或重新导入。两台设备需使用同一同步空间并可靠绑定书籍；A尚未联网发布的位置，B无法知道，不能承诺零延迟或强制退出后仍实时传送。

TXT/EPUB等重排文本同步内容锚点，不把屏幕第80页作为跨设备目标。建议记录固定bookUid、内容revision、章节/原文位置、摘录及前后文、设备、阅读会话、会话序号、事件ID及已知父事件。百分比用于展示与明确标识的近似回退；原设备页码仅参考。B可显示为第56页，但应位于A读到的同一句附近。PDF等固定版面才使用文档页索引及页内位置，此轮实施仍以TXT为首期。

复用canonical locator但验证真实生产/恢复链路；不能只给记录添加一个版本字段就认为定位可靠。TXT被编辑后先按修订映射旧锚点；定位涉及删改、净化不明、版本缺失则保留原位置，显示需要处理。精确定位失败不能静默用百分比并宣称无缝续读。

### A设备发布与B设备打开

1. A翻页或滚动停稳后，本地持久化位置事件及待同步项；持续阅读按建议5～10秒上限合并上传，离开阅读/切后台尝试立即刷新。参数需真机验证，系统挂起不作为唯一上传时机。只有真实阅读导航产生新事件，恢复、重新排版及同步回放不能产生“新阅读”。
2. B回前台提前检查；点击书籍时再次验证进度新鲜度，与本地解析并行。轻量进度任务优先于大文件上传，文件队列不能长期占用整个协调器。
3. 使用短且有上限的检查窗口（建议初始1秒，性能验收后调整），找到无分歧的新进度且正文版本可用，就在阅读第一屏出现前定位。必须等待远端应用完成后读取最新Book/locator，不能用点击时缓存的旧Book对象。
4. 超时/离线立即按本机位置打开，不无限转圈。晚到进度不再自动跳动，显示“手机有新的阅读位置 · 接着读”，用户点击应用；不把打开旧位置本身当作较新的阅读发布。
5. 阅读器已打开时收到进度同样只提示。应用一次后抑制该事件的重复提示；用户忽略后继续本机会话，重新出现提示需有新的远端阅读事件。
6. 若远端进度依赖尚未到达的TXT版本，先检查版本可用性。正文按既定范围与网络偏好获取，未就绪显示“阅读位置已收到，等待正文更新”；可从本机继续，不把新版offset套在旧文件上。

### 接续撤回

应用另一设备的位置前保存本机原锚点、正文版本和会话来源。成功后短暂显示“已接续手机的阅读位置 · 返回本机原位置”；提示消失后仍可从阅读器的续读详情返回，不能只靠会消失的Toast提供入口。

返回恢复本机位置，阻止同一远端事件立即再次自动接续；真正继续阅读后才按新的本机会话发布，不因自动恢复/撤回回调反复制造进度事件。本机原位置所属正文已变化时先映射锚点，无法可靠定位则保留原摘录并提示，不盲目跳转。各设备最近位置保留在详情中，已移除或无记录设备不显示虚假位置。

### 谁的位置算最新

- 区分“事件产生时间”“上传时间”“接收时间”。旧设备晚联网或晚扫描不能被包装成最新阅读；当前通用HLC单胜者规则需要针对进度加语义，不能单凭扫描时间排序。
- 每设备保存自身会话事件，并携带已看到的前序进度。已知因果顺序时，后续真实阅读自然接替前序；会话序号防重复和乱序，不以跨设备裸时间戳决定可靠顺序。
- 两台设备均离线阅读或同时前进、没有先后依据时，保留各自最新位置和“最远读到”摘要。进入B优先保留其未同步本地位置，提供另一个设备的续读候选，不弹正文编辑式合并对话框，不用max百分比强制覆盖。
- 用户主动回到第20页重读也是有效最新位置。临时搜索预览、查词跳转与恢复过程不推进主续读位置；显式目录跳转/正常翻页则按阅读行为记录。进一步以既有导航语义确认，不用任意停留时长猜意图。
- 进度接收只更新同步候选与已确认的恢复位置，不能直接覆盖活动阅读器内存中的位置再被旧保存回写。需要会话所有权/版本检查，并在本地保存、应用远端及界面通知之间统一协调。

### 验收

- A到某句→正常网络下成功上传→B打开第一屏接续同句；改变字号、窗口、横竖屏后仍对齐内容。
- B原本停在较早处、已运行超过15分钟内反复开书、书架缓存旧Book时，均读取最新可用进度。
- A持续阅读时定期发布；A强制退出仅保证已持久化可重试，不虚报未上传事件已上云。
- 网络慢/断网可及时开书；迟到消息和活动阅读不跳页，不发生旧恢复进度反向覆盖。
- 双端离线、时钟偏差、主动回读、重复事件、恢复触发保存均不会错误抢占续读位置。
- 大文件上传中仍可处理独立进度；文本版本不匹配时诚实显示等待，版本到达后定位正确。
- 进度开启/正文关闭，两端同版已有TXT可续读；关闭自动接续时保留本机位置和手动接续入口。
- 新设备空书架/初始化0%不覆盖远端；本机真实回读记录不被误删；初次合并中断可继续且不全库下载。
- 独立导入相同TXT能可靠关联；同名异文、多重匹配和已绑定不同身份不误合并、不丢注释。
- 接续后返回本机原位置；提示消失后仍可返回；同一远端事件不重复拉回，正文版本改变时先校验锚点。
- 阅读位置成功、正文等待/失败时详情分别准确显示；不同设备保持各自字号、主题及翻页偏好。

## 冲突与合并

保存共同版本B、本地L、远端R；时间只展示，不决定正文谁覆盖谁。

| 与B相比 | 处理 |
| --- | --- |
| 双方均未变化 | 不传输 |
| 仅L变化 | 自动更新云端当前TXT |
| 仅R变化 | 自动更新本地同一本书 |
| L、R内容一致 | 确认收敛，不生成副本 |
| 双边变化且基线、精确修改范围可靠不重叠 | 验证后合并，生成双父修订 |
| 同处修改/同点插入/无可靠基线 | 保留B/L/R，交给用户对照 |

首期必须具备单边自动同步和冲突保双份；自动合并只开放已验证的非重叠操作。外部全文件改动若无法可靠生成三方差异，则保留两份，不用AI改写或猜测正文。

冲突页定位分歧段落，手机上下、桌面左右对照，显示设备/时间/变化摘要。提供使用本机、使用另一版本、手动合并、另存副本。被舍弃分支仍进历史；解决后生成新修订自动同步，不偷偷用较晚时间胜出。

## 真正的文件保存与位置

新链路：原始TXT解码R → 用户修改R′ → 新TXT文件 → 净化规则 → 阅读排版。主题缩进、段距和规则净化不写入云端正文。

现有TXT `.data` 是派生归一化UTF-8缓存，章节正文范围还排除了标题/部分边界空白。不可从阅读章节拼回整书，也不能把缓存byte offset当作原文件偏移。只替换原文确切范围，范围之外保留正文、标题、换行和结尾。

第一版建议UTF-8保持既有BOM/换行，其他编码首次编辑保存前明确提示转UTF-8并保留原字节版本；严格验证解码，不能用含替代字符的宽松解码覆盖全书。编码不确定先要求选择正确编码/保留草稿。流式构建新文件，哈希/重索引在后台执行；WebDAV首期上传完整TXT，不宣称只传改动的几个字。

### 本地可恢复提交

文件与SQLite没有共享事务：捕获基版本 → 临时新文件落盘校验 → 数据库提交修订及文件操作/同步日志 → 原子切换工作文件或受控快照指针 → 确认对应后提示保存成功。启动补完或回滚未完成阶段，避免文件已改而任务丢失。

上传读取固定不可变快照。下载写临时文件，验证hash/字节数，落盘前检查计划捕获的本地版本，再更新原书；不重新导入制造新身份。

### 笔记与进度

原文版本、章节范围和修改操作提供旧→新坐标映射。当前txt-$index章节ID和大章分片不能被视为跨编辑天然稳定；先转原文范围，再映射到新版章节。

不相交批注精确迁移；覆盖删改的笔记保留摘录并标不可定位，不能随便挂到相邻文字。净化前后无现成映射的旧批注需引用核验，不能仅靠数字offset迁移。

同步顺序是内容版本可用→定位解析→笔记/进度展示。新版正文未到先保留依赖记录；不能把新offset画到旧书。正文、分页、滚动分段、截图、搜索、朗读使用同一版本签名，旧异步结果不能覆盖新版本。

## 云端协议

### 稳定身份与版本

固定documentId/bookUid；每次保存独立revisionId、父版本、hash、大小、编码与设备。已有云书沿用绑定UID，即使字面是sha256:旧hash也冻结；新书生成独立身份。

迁移覆盖书籍/文件绑定/进度/书签/笔记/会话/脏记录/游标/旧键别名，避免扫描产生伪删除。内容hash可用于重复检测，但不替代书籍身份。

```text
OpenReading/v2/
  space.json
  books/书名/书名.txt          ← 当前TXT，绑定后稳定更新
  revisions/<documentId>/...   ← 修订及历史内容
  devices/...                 ← 增量通知及设备状态
```

同名目录仅首次关联时区分，改文不创建书名(2)/书名(3)。重命名默认改书架名称，远端路径迁移是独立可恢复操作，不改变身份。

### 并发发布与中间态

1. 先上传不可变新内容/修订准备记录并校验，持久化发布任务。
2. 用当前目标TXT的强ETag条件写更新同一路径。失败重新拉取比较，不降级无条件覆盖。
3. 若采用临时MOVE，条件必须针对目标资源；只校验临时源文件或Overwrite:T不能保护目标。
4. 文件成功、描述符失败显示“文件已上传，正在确认”；持久日志补发。其他设备按准备记录、实际hash和ETag识别中间态，不立即当损坏或回写旧版。
5. 文件发布失败不推进共同基线。响应丢失先核对该修订是否已成功再幂等重试。
6. 现有增量通知可复用，但正文分支不能由HLC单胜者存储吞掉，需独立修订模型。

可靠条件写需用专用临时探测文件验证，不在用户书上试错。无/弱ETag、服务商忽略条件时保留本地和不可变分支，明确提示需处理，不冒充已同步或无条件覆盖。

依据：[RFC9110 If-Match](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1)、[RFC4918 If](https://www.rfc-editor.org/rfc/rfc4918.html#section-10.4)、[MOVE](https://www.rfc-editor.org/rfc/rfc4918.html#section-9.9)。规范不代替真实服务商能力测试。

### 外部软件修改云端TXT

首期至少检测已绑定路径的ETag/内容变化。与描述符不一致时区分未完成发布、外部修改和损坏；下载稳定、完整、可解码后保存为外部候选版本。有可靠祖先才自动接受，否则提示对照，绝不以旧元数据恢复覆盖。不扫描全网盘，不自动关联陌生同名文件，不承诺外部半写入文件可即时同步。

## 历史、删除与迁移

历史显示设备、时间、修改摘要，支持查看/比较/恢复；恢复生成新版本，原当前版仍能找回。首期不自动永久清理远端历史，显示占用并允许主动管理；后续清理也需保留当前版、冲突、待提交和必要共同祖先。祖先缺失时进入冲突，不能猜测覆盖。

移除本机下载保留云端及关联，有未同步修改时先保留恢复副本；从同步书库删除才传播明确删除标记。临时404/权限错误不视为删除；删除与离线编辑竞争保留编辑副本供恢复/另存。

推荐可变文件协议采用v2独立空间，可恢复地从v1导入并保留旧UID关联，v1不自动删除。新客户端只向v2写修订，旧客户端留在v1，不能触及新当前文件。

首次升级后当前TXT位置可能由v1迁往v2，升级页明确展示新位置；后续持续更新这个绑定，旧外部快捷路径不会自动更新。若必须原路径不变，需要全部客户端先具备协议门禁并通过兼容验收，另行原地迁移；不能让新旧算法同时写同一可变文件。

升级说明已关联TXT以后自动同步正文，保留用户范围关闭、自动同步暂停及网络选择，不扩大到未上传书籍。迁移幂等、可续做，失败不清空重建书库。

## 实施和验收

首期范围：TXT正文编辑与基本版本恢复、稳定身份/同书关联、首次连接安全合并、开书自动接续及撤回、单边正文双向同步、持久离线重试、正文冲突保留及手动解决、以续读为核心的设置页与分项同步状态。保留设备排版偏好；基本历史恢复纳入首期，复杂历史管理不作为首期前置。

后续增强：首页续读卡片、可靠的非重叠正文自动合并、复杂历史筛选/存储策略。在线书及EPUB正文编辑不进入本轮。

顺序：稳定身份/版本/事件与恢复日志、迁移门禁 → 首次合并与同书关联 → TXT原文编辑与基本恢复 → 轻量进度发布/开书接续与撤回 → 单边正文自动上传接收及版本依赖 → 状态调度/暂停重试与冲突手动解决 → 新设置页与分项详情 → 迁移及服务商端到端验收。旧版隔离在新写入开放前完成；实现顺序不代表允许发布缺少冲突保全的中间版本。

必须通过：

- 两设备相互编辑、真实云端TXT内容/hash正确，无需重导入，不新增书架项或每版编号目录。
- 离线保存/重启、上传中断、文件成功描述符失败都可恢复，不丢改文、不无限回传。
- 上传中再保存、下载中本地编辑、双端冲突保双份，解决后收敛。
- 编码/BOM/CRLF/emoji、修改区外原文、章节/大章分片、净化显示及批注位置正确。
- 仅本机不上传、仅云端不自动全库下载、暂停保任务且不继续新网络写入。
- 强条件写竞争、412、弱/缺失ETag、响应丢失、临时404、配额不足不损坏当前文件。
- 元数据成功文件失败必须部分完成，较新本地版本不被较早上传完成事件清脏。
- v1/v2并存、迁移中断重试不伪删除，不把旧客户端变化写进新当前库。

本轮只做代码/协议核对和文档设计；没有实现TXT编辑、运行新同步测试或连接真实WebDAV。

- `lib/services/books/txt_edit_service.dart`、`txt_edit_reference_service.dart`：原文件修订、崩溃恢复、正文与笔记/书签定位处理。
- `lib/services/sync/mutable_txt_sync_service.dart`、`webdav_book_file_service.dart`：稳定书籍绑定、当前正文/历史/编码描述符、持久任务、双向接收和冲突。
- `lib/services/sync/reading_progress_sync_service.dart`、`reading_progress_event.dart`：阅读事件顺序、多设备候选及接续撤回。
- `lib/pages/reader/book_reader_launcher.dart`、`native_reader_sync_continuation.dart`：开书检查与阅读中提示。
- `lib/pages/settings/sync/webdav_sync_page.dart`、`txt_sync_details_page.dart`：云端同步首页与单书正文状态。
- `lib/services/sync/webdav_sync_controller.dart`、`automatic_sync_scheduler.dart`：独立进度/文件调度及重试。

复用现有 Flutter/Provider 组件、BookDao、定位编码器、Dio/WebDAV 客户端和 GBK 解码依赖；没有新增应用依赖。同步入口整合为“云端同步”，文件与进度保持独立状态，版本恢复作为次级操作。
