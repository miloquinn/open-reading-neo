# WebDAV 错误诊断与版本选择评估

日期：2026-09-05。场景：坚果云，点击“立即同步”后提示“不支持安全同步所需的能力”。

## 结论

“最新修改优先”适合作为版本选择原则，但必须区分修改发生时间、发现修改时间和上传时间。选择哪份数据，与提交时防止另一台设备插入新修改，是两个独立问题。当前截图没有 HTTP 响应，不能证明坚果云缺少条件写入能力，也不能据此评价账号或存储安全。

推荐顺序：先按已知版本继承关系判断新旧；互不继承的修改按实际编辑时间选择默认版本，同时保留另一份；时间缺失、明显异常或涉及删除时保留冲突供用户处理。时间优先不能取消上传前的版本条件检查。

## 一手资料

- [HTTP RFC 9110 §13.1.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1)：If-Match 用于防止多个客户端并发覆盖。§8.8.2.2 说明 Last-Modified 通常是弱校验器，存在秒级精度等限制；§13.1.4 的 If-Unmodified-Since 也要求服务端实际执行条件判断，不能由客户端比较时间代替。
- [Syncthing 冲突处理](https://docs.syncthing.net/users/syncing.html#conflicting-changes)：内容不同的并发修改中，较旧修改时间的文件成为冲突副本；同时间使用设备身份确定结果；副本仍同步到其他设备。
- [坚果云官方冲突说明](https://help.jianguoyun.com/?p=1129)：两台离线设备分别修改会产生冲突，客户端保留两份内容。此说明针对坚果云客户端，不证明第三方 WebDAV 接口具备任何特定条件请求能力。

## 当前代码事实

| 数据 | 当前规则 | 与“最新修改”的差距 |
| --- | --- | --- |
| 阅读进度 | 保存位置时记录 saved_at、设备序号及版本向量；已知后续事件优先，独立并发事件留作候选 | 已能避免迟到旧进度覆盖已知新事件；并发候选没有直接按时间自动选中 |
| 其他元数据 | 按记录比较 HLC，时间相同由逻辑计数及设备 ID 决定 | 部分 HLC 在扫描发现变更时生成，并非业务编辑时间；不能宣称已经严格按最后编辑时间处理 |
| 可编辑 TXT | 内容哈希、共同基础版本、强 ETag 条件写入；并发变更保留快照并提示冲突 | 现有协议不包含足以比较所有设备实际编辑顺序的统一事件信息，不适合直接用网盘文件时间覆盖 |
| 普通书籍原文件 | 独立文件传输路径 | 不应受没有使用的可编辑 TXT 能力检测影响 |

## 本轮修正

1. WebDAV 异常传递结构化请求方法、资源路径、HTTP 状态及实际原因；连接测试也保留原异常。资源诊断不收集账号密码、Authorization、URL 查询参数或响应正文。
2. 服务端 5xx（507 容量不足除外）单独分类；条件写入检测遇到超时、限流、权限或服务异常，保留原原因。只有 HTTP 412 可以证明测试的旧版本条件被拒绝，409/423 不再误判为能力验证成功。
3. 条件请求被忽略时指出具体 If-Match 或 If-None-Match；界面展示可选择复制的错误详情。
4. 没有当前空间中启用的 TXT 待上传任务时，跳过可编辑 TXT 能力检测；仅检查远端更新或已暂停的书籍也不执行写入探测。
5. 元数据与 TXT 文件错误分别保留，元数据同步成功不抹掉文件失败；文件重试成功后清除相应失败。

这些变更不改变远端数据格式或已有冲突处理策略。

## 推荐的后续版本策略

- 阅读进度：延续已有因果顺序，互相独立的候选以实际 saved_at 推荐较新位置，保留旧位置供返回；不能选择页码最大的进度，因为用户可能主动回读。
- 设置、笔记等：在业务保存事务中记录修改事件，不在同步扫描时赋予“刚刚修改”的时间。按字段或独立记录合并，删除保留 tombstone。
- TXT：编辑提交时持久化 revision_id、parent_revision、edited_at、device_id；因果关系优先，并发且时间可信时“新版主文件 + 旧版冲突副本”，删除和时间异常另行处理。保留当前本地文件原子替换与快照恢复机制。
- 不具备条件写入能力的 WebDAV：优先评估只追加不可变版本、每设备独立索引、由客户端下载计算当前版本的兼容协议，而不是裸 PUT 覆盖共享 current 文件。必须同时解决旧客户端互通、索引完整性、目录分页、版本回收以及移动端暂停恢复；仅更换一次时间比较无法完成此迁移。

后续协议变更应覆盖：离线旧编辑晚上传、设备时钟快慢/回拨、同一秒修改、双方修改不同内容、删除与修改并发、上传中断后恢复、旧新客户端混用和历史版本恢复。本轮只完成诊断与独立功能门禁修复，未上线“TXT 并发时自动选择较新文件”的新协议。

## 验证边界

本地自动化使用模拟 HTTP 适配器及 SQLite/文件系统回归验证错误透传、条件请求、无任务门禁、状态恢复和已有 TXT 冲突保护。未使用用户凭据连接坚果云，未做两台实机联调；截图中的那次 HTTP 失败仍需要更新版本后的错误详情才能确定。
