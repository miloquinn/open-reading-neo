# WebDAV 同步协议与维护约定

更新：2026-09-15，按用户决定简化首版为「正文修改后整本上传」。本文是当前云端协议的唯一设计入口；替代旧的 current/history、可变 head 及 v1/v2/v3 多模式方案。本次为不兼容的协议替换，根标记 `schema_version: 2`，与历史目录名 `v2/` 无关。

## 云端目录

用户配置的根目录中保存以下对象。书名、作者和原文件名保存在元数据及修订清单中；书籍目录使用稳定 UID 的 SHA-256，改名不会移动数据。

```text
<同步根目录>/
├── format.json                         # 协议、空间 UUID、编码约定
├── changes/
│   └── <device-id>/
│       └── <12位序号>-<batch-sha256>.json
├── checkpoints/
│   └── <device-id>/
│       ├── <12位序号>-<index-sha256>.json
│       └── pages/<page-sha256>.json
├── books/
│   └── <sha256(book_uid)>/
│       ├── revisions/<manifest-sha256>.json
│       ├── chunks/<hash前两位>/<sha256>.bin  # 每个对象是一份完整书籍
│       ├── assets/<sha256>.<扩展名>       # 持久封面
│       └── source/revisions/<bundle-sha256>/
│           ├── book.json               # 书源章节状态
│           └── ...                     # 清单引用的来源历史/附件
└── exports/
    └── <书名>-<uid摘要前12位>/
        └── <revision-id>.<原扩展名>    # 用户手动导出的完整文件
```

不维护共享 `head.json`、`current.txt`、可变全库索引或另一套整书同步模式。`format.json` 是唯一不按内容寻址的协议对象：初始化一次并回读，已有不兼容标记拒绝覆盖。目录列表用于发现，清单与对象哈希用于验证，单次不完整列表不能抹掉已知基线。

云端正文块和导出都是未加密的原始字节；元数据也是 JSON。密码、账号令牌、AI 密钥、设备绝对路径、SQLite 数据库、分页缓存不上传。书源仍受既有公开身份/凭据过滤规则约束。

## 正文：一种修订协议

`BookRevisionRepository` 负责不可变修订；TXT、EPUB/PDF 等所有格式在修改后流式上传完整文件，共用发布、恢复和冲突规则。内容定义分块算法与增量上传分支已删除。清单的 `chunks` 列表固定写入一个完整文件引用；保留该协议字段和已有多对象修订的读取能力，避免使已提交数据不可恢复。

清单包含 `protocol: open-reading-book`、`schema_version: 2`、`book_uid`、`parents`、整书 `sha256`、`size`、`format`、`original_file_name`、有序 `chunks`，以及来源资料摘要和引用。修订 ID 是实际 JSON 字节的 SHA-256，不是时间戳。相同输入可复用同一提交，解析不依赖字段排列。

发布顺序：本地快照 → 来源附件/完整书籍 → 回读校验 → 修订清单 → 回读校验 → 本机完成标记 → 元数据文件描述。清单是正文提交点。未完成的上传不成为可用书籍，失败重试复用已经确认的完整文件；损坏或中断的不可变对象只允许用其地址对应的正确内容修复。

接收端验证清单身份、父引用和文件大小，流式下载并校验整书 SHA-256。书籍更新沿用本地 apply journal、临时文件、备份和恢复机制。活动阅读/编辑期间先暂存，不在使用中替换。正文变化后沿用现有定位验证/失效逻辑，保留笔记和书签。

父子关系决定正常前进；多个互不继承的末端修订构成冲突，不按上传时间静默覆盖。用户选择保留本机或使用远端时，保存双方快照，并提交引用当前全部末端的合并修订。选择期间出现新云端分支或本地编辑，旧选择被拒绝，需要刷新。使用远端先提交决定再落地文件；失败时保留可重试状态。

本机 `remote_version` 保存修订 ID，`current_path` 保存清单路径。已有本地 `head_version` 列仅作为修订 ID 的适配字段保留，不对应云端 head，也不再运行旧协议。上传期间的新编辑保持待同步，不能被旧上传的完成标记吞掉。

## 整本上传成本和本地缓存

- 无变化的书籍不重复上传或下载；阅读进度仍独立走小型元数据日志。
- 正文哪怕只改几个字，也上传完整的新版本。上传后回读校验，一次修改通常需要约 N 字节上传和 N 字节校验下载，另有小型清单及来源资料成本。
- 首次恢复需要完整书籍文件。读取、哈希与传输使用流，不将大书整本加载进内存；仍需要顺序 I/O 和快照/临时文件磁盘空间。
- 发布清单失败而书籍对象已验证成功时，重试复用该完整对象；这属于失败恢复，不是正文增量同步。
- 应用内编辑显式入队；外部文件观察结合路径、大小、mtime、ctime，最长 15 分钟重新哈希。最终提交和应用仍做内容校验。
- 普通自动进度周期不会因阅读位置变化就扫描所有正文。正文有待办/失败、远端文件描述变化或 15 分钟审计到期时，才触发正文对账。
- 文本清单读取限 16 MiB；非 TXT 文件同步/恢复仍限制 100 MiB，封面 10 MiB。TXT 仍使用流式传输，不新增 100 MiB 限制。

## 元数据与长期使用

`SyncEngine` 保留业务适配器、稳定记录 ID、HLC、删除标记及阅读事件语义。每个安装写自己的连续不可变日志；批次最多 1 MiB。按序应用，缺序号或损坏数据不跳过、不推进成功游标。不同设备的记录按既有数据域规则合并，正文分支冲突独立处理。

`MetadataCheckpoint` 在第 1 批及每 128 批生成分页检查点。每个检查点只包含该写入者实际发布过的记录及 tombstone，已发布视图保存在 SQLite `sync_published_records`，避免每次翻页重写巨大 JSON 状态。

新设备/落后设备先恢复最新检查点，再读剩余日志；全部分页成功应用后才推进主游标。维护时保留最近两个已验证检查点，确认其远端页面仍可读，再删除本设备在较旧检查点序号以内的日志和已失去引用的旧检查点页面。清理失败独立记录，不把已成功发布的数据误报为上传失败。

安装身份存入安全存储，与数据库备份分离；Apple 使用仅限本设备的 Keychain 属性。更换安装身份后使用新设备写入目录，不接着覆盖备份中原设备的日志。缓存、游标、待办按连接、空间 UUID 及安装身份隔离；删除并重建云端空间不会复用旧完成状态。

**正文历史和缓存尚未自动回收。** 当前会保留历史清单、完整文件版本、来源资料及本机快照；修订发现仍需列举该书的全部清单，缓存减少内容读取但不能消除随版本数增长的列表成本。以后引入正文压缩/回收时，必须另行定义保留期、可验证恢复点和长期离线设备重新加入规则。不能直接按文件年龄删除书籍对象，也不能把缓存当唯一恢复来源。

## 传输、重试与诊断

协议数据不再依赖强 ETag、`If-Match`、WebDAV LOCK、MOVE 或服务端拼接。可选通用可变存储接口仍保留条件写保护，但正常正文/日志不调用旧安全探针。

HEAD 不支持时回退到 Depth:0 PROPFIND；OPTIONS 405/501 不否定基本能力。目录请求显式索取 `resourcetype`，损坏/不可读的目录响应报错，不当作空云端。认证重定向限同源，文件流在同源重定向时重新打开。

元数据与正文分开执行；非全局元数据错误不饿死文件任务。自动调度遵守退避，已加入同步的书籍保存持久失败次数和下次重试时间；手动重试可以立即发起。进程被系统终止后不承诺继续传输，下次启动恢复待办。

概览页提供复制诊断，HTTP 记录有界、按资源类别脱敏，包含方法、状态与耗时，不包含凭据、URL、书名或正文。诊断表示本设备观察到的状态，不能证明离线设备已经收到数据。

## 旧数据与升级

全部参与设备需升级并配置同一个新的空根目录。已有不兼容 `format.json` 时提示选择新目录；不自动导入、删除或改写旧云端内容。未带标记的历史目录也不进入新协议读取范围。仅有旧云端备份的用户需要先用能读取旧备份的版本恢复本机书籍，再加入新同步空间。

完整可读文件通过“导出完整文件”显式生成，目录按修订命名，导出失败不改变同步成功状态。它是该修订的副本，不随以后的同步自动更新；外部软件编辑导出文件不会被当作正文同步输入。

## 首版页面层级与换机

```text
云端同步：状态、最近同步时间、立即同步
├── 阅读进度：进度开关、打开书籍自动接续
├── 书籍文件：待上传 / 可下载 / 已同步
│   └── 更新与冲突：暂停、重试、选择版本、手动导出
├── 同步设置：自动同步频率
│   ├── 更多同步内容：书架、书源、书签、笔记、统计与偏好
│   ├── 存储连接：WebDAV 配置和测试
│   └── 同步详情与问题：分项状态、完整错误、复制诊断
└── 换机指南：已有书籍 / 缺少书籍 / 编辑版本的区别
```

首页不重复显示详细开关、数据范围长列表、错误技术信息或断开连接按钮。有错误时仅给出短摘要和详情入口。同步文件开关由书籍文件页管理，进度开关只在阅读进度页管理。

只同步进度不要求上传正文：本地文件最初按内容哈希分配稳定书籍身份，两台手机自行导入相同文件可关联；在线书按书源 ID 和书籍 ID 关联。书名相同不构成匹配。旧手机编辑过的本地书保留原身份，但新手机单独导入编辑后的文件可能形成另一身份；此时应通过云端书籍下载保留关联。新手机没有正文时，单独的阅读进度无法变成可打开的书籍。

## 自动同步频率（2026-09-15）

设置页只有一个「自动同步频率」入口，弹出选择：及时同步、每 15 分钟、每小时、每天一次、关闭（仅手动）。首页显示当前频率，不增加新的开关或设置页面。旧配置中的自动同步开启/关闭分别迁移为及时同步/仅手动；保存连接时保留频率。

定期模式按上次完整自动同步成功后的实际间隔计算，每天一次表示 24 小时，不指定午夜或某个时刻。时间持久保存在本机偏好，关闭或重启应用不重置水位；更换云端连接或清除配置时重置。到期时应用未运行，下次启动或回前台补同步，不能承诺系统终止 App 后仍会定时运行。

阅读事件、退出阅读器、正文编辑、自动新书队列、打开书籍和前台轮询都遵守所选间隔。定期模式下开书接续已经同步的位置，需要最新位置可手动立即同步；关闭后不做自动网络请求。手动同步和用户主动上传/下载不受自动间隔限制。

失败重试保留退避，不推进自动成功时间；需要传输文件时等待文件完成，并在本轮再次发布文件描述，避免每天模式下新书/新版本再等一天才能被其他设备发现。本地修改仍持久保存，频率仅决定自动网络请求的时机。

本轮验证：31 个隔离运行的 Flutter 测试文件共 233 项通过，覆盖间隔门禁、重启恢复、失败退避、手动同步、文件完成后再记录成功时间，以及频率选择和首页摘要。定向静态分析无问题，macOS 无签名 Debug 产品构建通过；已检查实际字体渲染的频率选择器和首页截图。真实网盘及 iOS/Android 实机后台行为仍待验证。
