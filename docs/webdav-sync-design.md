# WebDAV 同步协议与维护约定

更新：2026-09-15。本文是当前云端协议的唯一设计入口；替代旧的 current/history、可变 head 及 v1/v2/v3 多模式方案。本次为不兼容的协议替换，根标记 `schema_version: 2`，与历史目录名 `v2/` 无关。

## 云端目录

用户配置的根目录中保存以下对象。书名、作者和原文件名保存在元数据及修订清单中；书籍目录使用稳定 UID 的 SHA-256，改名不会移动数据。

```text
<同步根目录>/
├── format.json                         # 协议、空间 UUID、编码约定
├── changes/
│   └── <device-id>/
│       └── <12位序号>-<batch-sha256>.json
├── checkpoints/
│   └── <device-id>/
│       ├── <12位序号>-<index-sha256>.json
│       └── pages/<page-sha256>.json
├── books/
│   └── <sha256(book_uid)>/
│       ├── revisions/<manifest-sha256>.json
│       ├── chunks/<hash前两位>/<sha256>.bin
│       ├── assets/<sha256>.<扩展名>       # 持久封面
│       └── source/revisions/<bundle-sha256>/
│           ├── book.json               # 书源章节状态
│           └── ...                     # 清单引用的来源历史/附件
└── exports/
    └── <书名>-<uid摘要前12位>/
        └── <revision-id>.<原扩展名>    # 用户手动导出的完整文件
```

不维护共享 `head.json`、`current.txt`、可变全库索引或另一套整书同步模式。`format.json` 是唯一不按内容寻址的协议对象：初始化一次并回读，已有不兼容标记拒绝覆盖。目录列表用于发现，清单与对象哈希用于验证，单次不完整列表不能抹掉已知基线。

云端正文块和导出都是未加密的原始字节；元数据也是 JSON。密码、账号令牌、AI 密钥、设备绝对路径、SQLite 数据库、分页缓存不上传。书源仍受既有公开身份/凭据过滤规则约束。

## 正文：一种修订协议

`BookRevisionRepository` 负责不可变修订；TXT 和 EPUB/PDF 等格式共用父修订、发布、恢复和冲突规则。TXT 使用内容定义分块，最小 32 KiB、目标平均 64 KiB、最大 256 KiB；其他格式在同一清单中引用一个完整文件块。目标平均值不保证每种正文都有同样分布。

清单包含 `protocol: open-reading-book`、`schema_version: 2`、`book_uid`、`parents`、整书 `sha256`、`size`、`format`、`original_file_name`、有序 `chunks`，以及来源资料摘要和引用。修订 ID 是实际 JSON 字节的 SHA-256，不是时间戳。相同输入可复用同一提交，解析不依赖字段排列。

发布顺序：本地快照 → 来源附件/新块 → 回读校验 → 修订清单 → 回读校验 → 本机完成标记 → 元数据文件描述。清单是正文提交点。未完成的块不成为可用书籍，失败重试复用已经确认的块；损坏或中断的不可变对象只允许用其地址对应的正确内容修复。

接收端验证清单身份、父引用、块数/大小，再按顺序流式重组，校验每块和整书 SHA-256。书籍更新沿用本地 apply journal、临时文件、备份和恢复机制。活动阅读/编辑期间先暂存，不在使用中替换。正文变化后沿用现有定位验证/失效逻辑，保留笔记和书签。

父子关系决定正常前进；多个互不继承的末端修订构成冲突，不按上传时间静默覆盖。用户选择保留本机或使用远端时，保存双方快照，并提交引用当前全部末端的合并修订。选择期间出现新云端分支或本地编辑，旧选择被拒绝，需要刷新。使用远端先提交决定再落地文件；失败时保留可重试状态。

本机 `remote_version` 保存修订 ID，`current_path` 保存清单路径。已有本地 `head_version` 列仅作为修订 ID 的适配字段保留，不对应云端 head，也不再运行旧协议。上传期间的新编辑保持待同步，不能被旧上传的完成标记吞掉。

## 增量成本和本地缓存

- 无变化正文不重复上传或下载；比较清单和本地观察状态，缓存中的对象仍按哈希验证。
- 应用内编辑显式入队；外部文件观察结合路径、大小、mtime、ctime，最长 15 分钟重新哈希。它是优化提示，最终提交和应用仍做内容校验。
- 普通自动进度周期不会因阅读位置变化就扫描所有正文。正文有待办/失败、远端文件描述变化或 15 分钟审计到期时，才触发正文对账。
- TXT 局部编辑通常复用大量旧块；清单仍包含整本书的块顺序，因此清单成本随块数增长。首次同步必须传全部缺失内容，首次恢复必须取得完整所需内容。
- 新块上传后有完整校验回读，因此会产生相应下载流量。流量计数包含对象载荷和验证回读，不包含 HTTP 头、目录 XML 等网络开销。
- 本地分块、快照和恢复仍有 O(N) 顺序 I/O，并需要磁盘空间；网络增量不等于本地编辑/保存瞬时完成。源资料和封面还有独立成本。
- 清单最多 100,000 个块，读取文本清单限 16 MiB。非 TXT 文件同步/恢复仍限制 100 MiB，封面 10 MiB。

## 元数据与长期使用

`SyncEngine` 保留业务适配器、稳定记录 ID、HLC、删除标记及阅读事件语义。每个安装写自己的连续不可变日志；批次最多 1 MiB。按序应用，缺序号或损坏数据不跳过、不推进成功游标。不同设备的记录按既有数据域规则合并，正文分支冲突独立处理。

`MetadataCheckpoint` 在第 1 批及每 128 批生成分页检查点。每个检查点只包含该写入者实际发布过的记录及 tombstone，已发布视图保存在 SQLite `sync_published_records`，避免每次翻页重写巨大 JSON 状态。

新设备/落后设备先恢复最新检查点，再读剩余日志；全部分页成功应用后才推进主游标。维护时保留最近两个已验证检查点，确认其远端页面仍可读，再删除本设备在较旧检查点序号以内的日志和已失去引用的旧检查点页面。清理失败独立记录，不把已成功发布的数据误报为上传失败。

安装身份存入安全存储，与数据库备份分离；Apple 使用仅限本设备的 Keychain 属性。更换安装身份后使用新设备写入目录，不接着覆盖备份中原设备的日志。缓存、游标、待办按连接、空间 UUID 及安装身份隔离；删除并重建云端空间不会复用旧完成状态。

**正文历史和缓存尚未自动回收。** 当前会保留历史清单、内容块、来源资料及本机快照；修订发现仍需列举该书的全部清单，缓存减少内容读取但不能消除随版本数增长的列表成本。以后引入正文压缩/回收时，必须另行定义保留期、可验证恢复点和长期离线设备重新加入规则。不能直接按文件年龄删除块，也不能把缓存当唯一恢复来源。

## 传输、重试与诊断

协议数据不再依赖强 ETag、`If-Match`、WebDAV LOCK、MOVE 或服务端拼接。可选通用可变存储接口仍保留条件写保护，但正常正文/日志不调用旧安全探针。

HEAD 不支持时回退到 Depth:0 PROPFIND；OPTIONS 405/501 不否定基本能力。目录请求显式索取 `resourcetype`，损坏/不可读的目录响应报错，不当作空云端。认证重定向限同源，文件流在同源重定向时重新打开。

元数据与正文分开执行；非全局元数据错误不饿死文件任务。自动调度遵守退避，已加入同步的书籍保存持久失败次数和下次重试时间；手动重试可以立即发起。进程被系统终止后不承诺继续传输，下次启动恢复待办。

概览页提供复制诊断，HTTP 记录有界、按资源类别脱敏，包含方法、状态与耗时，不包含凭据、URL、书名或正文。诊断表示本设备观察到的状态，不能证明离线设备已经收到数据。

## 旧数据与升级

全部参与设备需升级并配置同一个新的空根目录。已有不兼容 `format.json` 时提示选择新目录；不自动导入、删除或改写旧云端内容。未带标记的历史目录也不进入新协议读取范围。仅有旧云端备份的用户需要先用能读取旧备份的版本恢复本机书籍，再加入新同步空间。

完整可读文件通过“导出完整文件”显式生成，目录按修订命名，导出失败不改变同步成功状态。它是该修订的副本，不随以后的增量同步自动更新；外部软件编辑导出文件不会被当作正文同步输入。
