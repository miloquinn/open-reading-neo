## Bug Fixes

### Fixed malformed book URLs causing detail pages to 404

**Issue**: Some book sources' search/discover rules extract a single value (such as a book's detail URL) from a list item that contains more than one matching element — for example a row with both a book-title link and a separate "download" link. The rule engine concatenated every matched element's attribute value into one string instead of taking the first match, producing malformed URLs like two hrefs glued together. Opening the book then failed with an HTTP 404, even though search and discover results displayed normally.

**Solution**:

- When a rule resolves to a single value and matches multiple elements, take the first matching element's attribute instead of concatenating every match, in both the CSS/legacy selector engine and the XPath engine.
- This matches jsoup's `Elements.attr()` semantics and XPath 1.0's node-set-to-string conversion, both of which use the first matching node.

**Impact**:

- Book sources whose search/discover rows contain more than one link now resolve the correct book detail URL.
- Detail, catalog, and content requests that previously failed with HTTP 404 due to a malformed URL now succeed.

### Fixed content-cleanup rules erasing entire chapters

**Issue**: Many book sources define a `ruleContent.replaceRegex` to strip one injected watermark or anti-scraping line from chapter content, typically a pattern like `##.*some notice.*`. That cleanup step ran with a regex mode that let `.` match newlines, so the greedy pattern spanned from the start of a multi-paragraph chapter through the last occurrence of the target line and erased the entire chapter body instead of just that line. Affected chapters showed as empty with "Compatible source did not return chapter content."

**Solution**:

- Run the content replaceRegex cleanup step with line-scoped (non-dotAll) regex semantics, matching the sibling content-extraction step, which already opted into this behavior for the same reason.

**Impact**:

- Book sources that strip a watermark/notice line from chapter content via `replaceRegex` no longer lose the rest of the chapter.

### Fixed chapters appearing out of order when opening a catalog

**Issue**: Opening a book's table of contents could show chapters in the wrong order for some book sources.

**Solution**: Fixed the catalog ordering issue in the reading source engine.

**Impact**: Chapter lists now display in the correct reading order.

### Fixed overflowing stat cards on the Detailed Statistics overview tab

**Issue**: The stat cards on the Detailed Statistics page's "Overview" tab could overflow at the bottom under certain screen widths or larger system font sizes.

**Solution**: Adjusted the stat card layout to accommodate narrower widths and larger font scales.

**Impact**: Stat cards no longer overflow their bounds on affected screen sizes and font settings.
